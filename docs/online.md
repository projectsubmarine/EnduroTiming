# オンライン版（親システム：Firebase）

各ゴール（セクション）の端末から記録を送り、本部の結果をその場で更新するための拡張です（`online` ブランチ）。
従来のローカル版（`index.html` をダブルクリック）としての動きはそのまま残っています。

## しくみ

```
 ゴール端末（スマホ/PC）goal.html ──┐  入力記録（entries）を追記
 ゴール端末 …                     ├──▶  Firebase（Firestore）  ◀── 本部 index.html（名簿を送る・記録を受け取って順位計算）
 本部の③タイム入力 ───────────────┘
```

- **記録は追記のみ**（`events/{大会コード}/entries`）。訂正・削除も「新しい記録」として追加するので、サーバー上の記録は消えない。
  本部は全記録から `Core.runsFromEntries()` で runs を組み立て、従来どおり `Core.compute()` で順位を出す。
- **通信が途切れても入力できる**：Firestoreのオフライン保存で端末内に貯め、つながったら自動送信。
  ページ自体も端末に保存する（`sw.js`）ので、電波の無い場所で再読み込み・開き直しをしても入力画面が開く
  （一度、電波のある場所でページを開いておくこと）。
  さらにゴール端末は入力の控えを localStorage にも残し、サーバーに無ければ再送する。最後の手段として `.json` に書き出し、
  本部の「セクション記録を取り込む」で読み込める。
- **同じ項目に違う時刻が届いたら上書きしない**（先に入った値を採用し「競合」として表示）。本部が③の「編集」で正しい時刻を
  登録すると解消する。ゴール端末で既存の値を訂正するときは確認のうえ「訂正」として送る。
- **名簿は本部が正本**。本部でライダーを登録・変更すると自動でサーバーに送られ、ゴール端末に届く。
  名簿にないBIBの記録も受け付け、本部でそのBIBを登録すると自動で紐づく。
- **権限**：本部はGoogleアカウント（大会を公開したアカウント）。ゴール端末はログイン不要（匿名）で、
  本部が発行する「セクションごとの6桁PIN」で登録し、自分のセクションの記録だけ送れる・見られる（`firestore.rules`）。
  結果はスタッフのみ（一般公開ページは無い）。

## 初回の準備（1回だけ）

1. https://console.firebase.google.com でプロジェクトを作成（無料のSparkプランで足ります。Googleアナリティクスは不要）。
2. **Authentication** → ログイン方法 で「Google」と「匿名」を有効にする。
3. **Firestore Database** を作成（ロケーションは `asia-northeast1`（東京）など。モードは「本番環境」）。
4. プロジェクトの設定 → マイアプリ → ウェブアプリを追加 → 表示された `firebaseConfig` を `js/firebase-config.js` に貼る。
5. ルールとページを公開（このフォルダで。Node.js が必要）：
   ```
   npx firebase-tools login
   npx firebase-tools use --add          # 作ったプロジェクトを選ぶ
   npx firebase-tools deploy --only firestore:rules,hosting
   ```
   表示された `https://<プロジェクト>.web.app/` が本部用、`…/goal.html` がゴール端末用のページ。
   （GitHub Pages など別の場所で配信する場合は、Authentication → 設定 → 承認済みドメイン にそのドメインを追加する）

## 大会での使い方

1. **本部（大会前）**：`https://<プロジェクト>.web.app/` を開き、①でライダー登録まで済ませる →
   「データ管理 → オンライン」で Googleでログイン → 「この大会をオンラインに公開する」→ 大会コードが表示される。
   「セクションのPINを発行」で各セクションのPINを作る。
2. **ゴール端末（大会前・電波のある場所で）**：本部に表示される `goal.html?e=大会コード` を開き、セクション#・PIN・端末名を入れて登録。
   （登録が済めば、その後は電波が無くても入力できる）
3. **当日**：ゴール端末は「ゴール／スタート」を選び、BIBと時刻（計測器の表示 `100523.45` をそのまま）を入れて「登録」。
   DNF/DNS/DSQ はボタンで。画面上部に「✓すべて送信済み／未送信 n 件」が出る。
4. **本部**：③④は自動で更新される。③の上部に「競合」「名簿にないBIB」が出たら対応する。
5. **大会後**：本部で「バックアップを書き出す」。「切断する」とローカル版に戻る（サーバー上のデータは残る）。

## 注意・未対応

- 本部は1台を想定（2台目の本部PCは「大会コードで接続」で使えるが、名簿を同時に編集すると後から送った方が残る）。
- オンライン接続中は「サンプルデータ」「全データを消去」「バックアップを読み込む」は使えない（切断してから）。
- ゴール端末の登録を取り消すには、本部の「登録済みの端末」で「無効化」する。PINの再発行だけでは登録済み端末は止まらない。

## テスト

| コマンド | 内容 | 必要なもの |
|---|---|---|
| `npm test` | 計算ロジック・画面（jsdom）。オンライン部分は偽サーバーで確認（`test/online.test.js`） | なし |
| `npm run test:rules` | `firestore.rules` のアクセス権（`test/rules.test.js`） | Java（`brew install openjdk`） |
| `npm run test:e2e` | 実際のChrome＋Firebase SDK＋エミュレータで、本部とゴール端末を通しで動かす（電波なしでの入力・再読み込み・復帰後の自動送信を含む。`test/e2e/online.e2e.js`） | Java、Google Chrome |

エミュレータ用に `js/firebase-config.js` の設定へ `emulator:{firestore:'127.0.0.1:8080',auth:'http://127.0.0.1:9099'}` を足すと、
エミュレータにつながる（テストでは自動で差し替えている。本番の設定には入れないこと）。
